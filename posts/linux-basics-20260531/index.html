2026년 5월 31일

강의자료/02_2 리눅스 기초 이어드림스쿨 강의자료를 바탕으로, 리눅스 환경에서 꼭 알아야 할 기본 개념과 명령어를 정리해 보았다.

리눅스는 서버 개발, 클라우드, 네트워크 장비, 임베디드 기기, 안드로이드까지 넓게 쓰이는 운영체제다. 특히 개발자는 GUI보다 CLI 환경에서 서버를 다루는 일이 많기 때문에, 리눅스의 구조와 명령어에 익숙해지는 것이 중요하다.

1. 리눅스는 오픈소스 기반 운영체제다#

리눅스는 리누스 토발즈가 만든 운영체제 커널에서 출발했다. 자유 소프트웨어와 오픈소스 개발 문화의 대표적인 사례이며, GNU 프로젝트와 함께 성장해 왔다. GNU 프로젝트는 유닉스처럼 동작하지만 자유롭게 사용할 수 있는 소프트웨어 환경을 만들기 위해 시작되었다.

리눅스의 구조는 크게 하드웨어, 커널, 쉘, 응용 프로그램으로 나눌 수 있다. 커널은 하드웨어 자원을 관리하고, 쉘은 사용자와 커널 사이에서 명령을 해석해 전달한다. 사용자가 터미널에 명령어를 입력하면 쉘이 이를 해석하고 커널에 요청한다.

리눅스의 특징은 다음과 같다.

  • 유닉스 기반의 운영체제다.
  • 멀티 유저와 멀티 태스킹을 지원한다.
  • CLI와 GUI를 모두 사용할 수 있다.
  • 네트워크 기능이 강력하다.
  • 서버, 개발 환경, 임베디드 장비 등 다양한 분야에서 활용된다.

리눅스 배포판은 여러 종류가 있다. 레드햇 계열은 rpm 패키지와 yum을 사용하고, 데비안 계열은 deb 패키지와 apt를 사용한다. 우분투는 데비안 기반의 대표적인 리눅스 배포판으로, 개인용 PC와 개발 환경에서 많이 사용된다.

2. CLI와 쉘은 리눅스를 다루는 기본 통로다#

GUI는 아이콘과 창 같은 그래픽 요소로 컴퓨터를 조작하는 방식이고, CLI는 명령어를 입력해 컴퓨터와 상호작용하는 방식이다. 리눅스 서버는 화면 없이 터미널만 제공되는 경우가 많기 때문에 CLI 사용법이 중요하다.

쉘은 커널과 사용자 사이를 이어주는 프로그램이다. 사용자의 명령을 해석하고 커널에 전달한다. 리눅스에서는 기본 쉘로 bash가 많이 사용된다.

기초 명령어는 리눅스 환경을 탐색하는 출발점이다.

  • whoami: 현재 로그인한 사용자 ID를 확인한다.
  • passwd: 현재 사용자의 비밀번호를 변경한다.
  • pwd: 현재 디렉터리 위치를 출력한다.
  • ls: 현재 디렉터리의 파일과 폴더 목록을 출력한다.
  • ls -l: 목록을 자세히 출력한다.
  • ls -a: 숨김 파일과 디렉터리까지 출력한다.
  • cd: 다른 디렉터리로 이동한다.
  • --help: 명령어의 사용법을 확인한다.

우분투에서는 apt를 통해 소프트웨어를 설치, 제거, 업데이트할 수 있다. 예를 들어 apt install, apt remove, apt update, apt search, apt show 같은 명령을 사용한다. 다만 시스템에 영향을 주는 작업은 권한이 필요하므로 sudo를 함께 사용한다.

root는 리눅스에서 모든 권한을 가진 최고 관리자다. sudo는 일반 사용자가 일시적으로 관리자 권한을 얻어 명령을 실행하게 해준다. 편리하지만 시스템 전체에 영향을 줄 수 있으므로 신중하게 사용해야 한다.

3. 파일 시스템은 디렉터리와 권한을 이해하는 것에서 시작한다#

리눅스 파일 시스템은 파일과 디렉터리를 계층적인 트리 구조로 관리한다. 가장 위에는 루트 디렉터리 /가 있고, 그 아래에 /bin, /home, /lib, /usr 같은 디렉터리가 이어진다.

파일은 보조기억장치에 저장되는 데이터의 집합이고, 디렉터리는 파일과 하위 디렉터리를 정리하는 공간이다. 리눅스에서는 많은 것을 파일처럼 다루기 때문에 파일 시스템 구조를 이해하는 것이 중요하다.

ls -al 명령을 사용하면 파일의 속성과 권한을 확인할 수 있다. 파일 권한은 사용자, 그룹, 그 외 사용자에 대해 읽기, 쓰기, 실행 권한으로 나뉜다.

  • r: 읽기 권한이다.
  • w: 쓰기 권한이다.
  • x: 실행 권한이다.

권한은 숫자로도 표현한다. 읽기는 4, 쓰기는 2, 실행은 1이다. 예를 들어 chmod 777 file.txt는 사용자, 그룹, 그 외 사용자 모두에게 읽기, 쓰기, 실행 권한을 주는 명령이다. 하지만 실제 환경에서 777은 너무 넓은 권한이므로 꼭 필요한 경우가 아니라면 피하는 것이 좋다.

소유자는 chown으로 변경할 수 있다. chown user:group file.txt처럼 사용자와 그룹을 지정한다. 소유자 변경은 보통 관리자 권한이 필요하다.

파일과 디렉터리를 다루는 기본 명령어도 자주 사용된다.

  • mkdir: 디렉터리를 만든다.
  • touch: 빈 파일을 만들거나 파일의 시간을 갱신한다.
  • rmdir: 비어 있는 디렉터리를 삭제한다.
  • rm: 파일이나 디렉터리를 삭제한다.
  • cp: 파일이나 디렉터리를 복사한다.
  • mv: 파일이나 디렉터리를 이동하거나 이름을 바꾼다.
  • cat: 파일 내용을 출력하거나 이어 붙인다.
  • find: 조건에 맞는 파일이나 디렉터리를 찾는다.

텍스트 편집기로는 nano를 사용할 수 있다. nano file.txt처럼 실행하고, Ctrl + O로 저장하고 Ctrl + X로 종료한다. 서버에서 간단한 설정 파일을 수정할 때 유용하다.

4. 정규표현식, grep, 리다이렉션, 파이프는 CLI를 강력하게 만든다#

정규표현식은 특정한 규칙을 가진 문자열 집합을 표현하는 형식이다. 단순히 문자열 하나를 찾는 것을 넘어, 숫자 패턴, 시작과 끝, 반복 횟수, 선택 조건 등을 표현할 수 있다.

자주 쓰는 메타 문자는 다음과 같다.

  • ^: 문자열의 시작을 의미한다.
  • $: 문자열의 끝을 의미한다.
  • .: 임의의 한 문자와 대응한다.
  • \d: 숫자를 의미한다.
  • \w: 알파벳, 숫자, 언더스코어를 의미한다.
  • \s: 공백 문자를 의미한다.
  • *: 0개 이상 반복을 의미한다.
  • +: 1개 이상 반복을 의미한다.
  • ?: 0개 또는 1개를 의미한다.
  • {n,m}: n개 이상 m개 이하 반복을 의미한다.

grep은 파일 안에서 특정 문자열이나 패턴을 찾는 명령어다. grep elice hello.txt는 hello.txt에서 elice가 포함된 줄을 출력한다. grep -i는 대소문자를 구분하지 않고, grep -v는 패턴과 일치하지 않는 줄을 출력하며, grep -c는 일치하는 줄의 개수를 출력한다.

리다이렉션은 표준 입력, 표준 출력, 표준 오류의 흐름을 바꾸는 기능이다. >는 출력 결과를 파일로 저장하고, >>는 기존 파일 뒤에 이어 쓴다. 예를 들어 ls > ls.txt는 ls 결과를 화면이 아니라 ls.txt 파일에 저장한다.

파이프는 한 명령어의 출력 결과를 다른 명령어의 입력으로 넘긴다. head a.txt | grep [0-9]는 a.txt의 앞부분을 출력한 뒤, 그 결과 중 숫자가 포함된 줄만 찾는다. 리다이렉션과 파이프를 함께 사용하면 ls | grep user01 > output.txt처럼 검색 결과를 파일로 저장할 수 있다.

마운트는 물리적인 저장 장치를 특정 디렉터리에 연결하는 작업이다. 리눅스에서는 보조기억장치를 사용하려면 파일 시스템에 연결해야 할 때가 있다. mount, df, umount 같은 명령어는 디스크와 파일 시스템 상태를 확인하고 연결을 관리할 때 사용된다.

5. 프로세스, job, 예약 작업, SSH는 서버 운영의 기본이다#

프로세스는 실행 중인 프로그램이다. 리눅스의 각 프로세스는 고유한 PID를 가진다. 프로세스는 부모 프로세스와 자식 프로세스 관계를 가질 수 있고, 커널에 의해 관리된다.

프로세스 확인에는 ps 명령어를 사용한다.

  • ps: 현재 터미널에서 실행 중인 프로세스를 확인한다.
  • ps -ef: 전체 프로세스 목록을 자세히 확인한다.
  • ps aux: 실행 중인 프로세스를 사용자, CPU, 메모리 사용량과 함께 확인한다.

프로세스를 종료할 때는 kill을 사용한다. kill -15 PID는 정상 종료 요청이고, kill -9 PID는 강제 종료에 가깝다. 가능하면 먼저 정상 종료를 시도하고, 정말 멈추지 않는 경우에 강제 종료를 사용하는 것이 좋다.

job은 쉘에서 실행되는 작업을 의미한다. 작업은 foreground와 background로 나눌 수 있다. foreground 작업은 현재 터미널을 차지하고, background 작업은 뒤에서 실행된다. 긴 작업을 실행할 때 background 실행과 job control을 알면 터미널을 더 효율적으로 사용할 수 있다.

at은 특정 시간에 한 번 작업을 실행하는 예약 명령이고, cron은 정해진 주기에 따라 반복 작업을 실행하는 방식이다. 예를 들어 매일 새벽 백업 스크립트를 실행하거나, 매월 1일 특정 작업을 실행할 때 crontab을 사용할 수 있다.

SSH는 Secure Shell의 약자로, 원격 서버에 안전하게 접속하기 위한 프로토콜이다. Telnet도 원격 접속을 제공하지만 통신 내용이 암호화되지 않는 문제가 있다. SSH는 데이터를 암호화해 전송하므로 서버 접속과 원격 명령 실행에 널리 사용된다.

마무리#

리눅스 기초는 단순히 명령어 목록을 외우는 것이 아니라, 서버를 다루는 사고방식을 익히는 과정이다. 디렉터리를 이동하고, 파일을 찾고, 권한을 조정하고, 프로세스를 확인하고, 원격 서버에 접속하는 작업은 개발과 운영에서 계속 반복된다.

1. 핵심 주장#

리눅스는 개발자가 서버와 가장 직접적으로 대화하는 환경이다. CLI 명령어를 이해하면 파일, 권한, 프로세스, 네트워크 문제를 더 빠르게 파악하고 해결할 수 있다.

특히 서버 환경에서는 GUI가 없는 경우가 많기 때문에, 터미널에서 현재 위치를 확인하고, 파일을 읽고, 로그를 검색하고, 프로세스를 종료하고, 원격 서버에 접속하는 능력이 기본기가 된다.

2. 중요한 개념#

  • 리눅스는 오픈소스 기반 운영체제이며 서버와 개발 환경에서 널리 사용된다.
  • 커널은 하드웨어를 관리하고, 쉘은 사용자의 명령을 해석해 커널에 전달한다.
  • CLI는 명령어로 컴퓨터와 상호작용하는 인터페이스다.
  • apt는 우분투 계열에서 패키지를 설치, 제거, 업데이트하는 도구다.
  • root는 최고 관리자이고, sudo는 일시적으로 관리자 권한을 얻는 명령이다.
  • 리눅스 파일 시스템은 /를 루트로 하는 트리 구조다.
  • 파일 권한은 읽기, 쓰기, 실행 권한으로 나뉘며 chmod, chown으로 관리한다.
  • 정규표현식과 grep은 텍스트 검색을 강력하게 만든다.
  • 리다이렉션과 파이프는 명령어의 입력과 출력을 연결해 작업을 자동화한다.
  • ps, kill, job control은 프로세스 관리의 기본이다.
  • cron, at, SSH는 서버 운영과 자동화에 자주 쓰인다.

3. 내가 놓치기 쉬운 부분#

명령어의 결과만 외우고 표준 입력, 표준 출력, 표준 오류의 흐름을 놓치기 쉽다. 리다이렉션과 파이프를 이해하면 명령어를 하나씩 쓰는 수준에서 벗어나 여러 명령을 조합해 원하는 결과를 만들 수 있다.

권한도 단순히 chmod 777로 해결하려고 하면 위험하다. 권한은 사용자, 그룹, 그 외 사용자에게 필요한 만큼만 주는 것이 기본이다. 서버에서는 편의를 위해 권한을 넓히는 습관이 보안 문제로 이어질 수 있다.

프로세스 종료도 마찬가지다. kill -9는 강력하지만 항상 좋은 선택은 아니다. 먼저 어떤 프로세스인지 확인하고, 정상 종료가 가능한지 살펴본 뒤 필요한 경우에만 강제 종료해야 한다.

4. 현실에 적용하는 방법#

서버에 접속하면 먼저 pwd, ls -al, whoami로 현재 위치와 사용자, 파일 상태를 확인하는 습관을 들이면 좋다. 문제가 생겼을 때는 내가 어디에서 어떤 권한으로 작업 중인지 아는 것이 첫 단서가 된다.

로그를 확인할 때는 cat, head, tail, grep, 파이프를 조합해 필요한 줄만 빠르게 찾을 수 있다. 예를 들어 오류 로그에서 특정 키워드가 포함된 줄만 찾거나, 최근 로그만 보고 싶을 때 CLI 조합이 큰 힘을 낸다.

운영 작업은 반복되는 경우가 많다. 정해진 시간에 실행해야 하는 작업은 cron으로 자동화하고, 원격 서버 작업은 SSH로 안전하게 접속해 처리한다. 이렇게 하면 수동 작업을 줄이고 실수를 줄일 수 있다.

5. 나에게 물어볼 질문 5개#
