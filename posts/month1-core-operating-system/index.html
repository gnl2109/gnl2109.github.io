[이어드림스쿨6기_1개월] 02_1 핵심 운영체제

2026년 5월 31일

강의자료/02_1 핵심 운영체제 이어드림스쿨 강의자료를 바탕으로, 운영체제가 컴퓨터 안에서 어떤 역할을 하는지 정리해 보았다.

운영체제는 사용자가 직접 만나는 화면보다 더 아래에서 움직이는 시스템 소프트웨어다. CPU, 메모리, 저장장치 같은 하드웨어 자원을 관리하고, 프로그램이 실행될 수 있는 환경을 만들어준다. 우리가 앱을 실행하고, 파일을 저장하고, 여러 작업을 동시에 처리할 수 있는 이유 뒤에는 운영체제가 있다.

1. 운영체제는 하드웨어와 프로그램 사이를 관리한다#

컴퓨터에는 CPU, 메모리, 주변장치, 보조기억장치 같은 여러 하드웨어가 있다. CPU는 데이터를 연산하고 명령을 처리하는 장치이고, 메모리는 실행 중인 프로그램과 데이터를 임시로 올려두는 공간이다. 키보드, 마우스, 프린터 같은 주변장치는 사용자의 입력과 출력에 관여하고, SSD나 HDD 같은 보조기억장치는 데이터를 오래 보관한다.

운영체제는 이 자원들을 직접 다루기 어려운 사용자와 프로그램을 대신해 하드웨어를 관리한다. 단순히 프로그램을 실행시키는 것에서 끝나지 않고, 어떤 프로그램에 CPU를 줄지, 메모리를 얼마나 줄지, 파일을 어디에 저장할지, 네트워크 통신을 어떻게 처리할지 결정한다.

운영체제의 대표적인 기능은 다음과 같다.

  • 프로세스 관리: 실행 중인 프로그램을 관리한다.
  • 메모리 관리: 프로그램이 사용할 메모리 공간을 할당하고 회수한다.
  • 파일 시스템 관리: 데이터를 파일과 디렉터리 형태로 저장하고 찾을 수 있게 한다.
  • 네트워크 관리: 프로토콜을 지원해 통신이 가능하도록 돕는다.

Windows, macOS, Linux 같은 운영체제는 각각 특징이 다르다. Windows는 개인용 컴퓨터에서 널리 쓰이고, macOS는 Apple 기기와 결합된 환경을 제공한다. Linux는 오픈소스 기반으로 서버와 개발 환경에서 많이 사용된다. Docker 같은 컨테이너 기술도 운영체제의 자원 격리와 실행 환경 개념을 바탕으로 이해할 수 있다.

2. 프로세스는 실행 중인 프로그램이다#

프로세스는 실행 중인 프로그램이다. 프로그램은 저장장치에 있는 명령어와 데이터의 묶음이고, 프로세스는 그 프로그램이 메모리에 올라와 실제로 실행되는 상태다. 예를 들어 브라우저 아이콘은 프로그램이지만, 브라우저를 실행해 작업 중인 상태는 프로세스라고 볼 수 있다.

프로세스 안에는 스레드가 있다. 스레드는 프로세스 내부에서 실제로 실행되는 흐름의 단위다. 하나의 프로세스 안에 여러 스레드가 있으면, 같은 메모리 공간을 공유하면서 여러 작업을 나누어 처리할 수 있다.

프로세스의 메모리 구조는 보통 다음과 같이 나눌 수 있다.

  • 코드 영역: 실행할 명령어가 저장되는 공간이다.
  • 데이터 영역: 전역 변수나 정적 변수가 저장되는 공간이다.
  • 힙 영역: 실행 중 동적으로 할당되는 메모리 공간이다.
  • 스택 영역: 함수 호출, 지역 변수, 임시 데이터가 쌓이는 공간이다.

프로세스는 생성, 준비, 실행, 대기, 종료 같은 상태를 오간다. 준비 상태는 CPU를 배정받기 전 기다리는 상태이고, 실행 상태는 실제로 CPU를 사용 중인 상태다. 입출력 작업처럼 시간이 걸리는 일을 만나면 대기 상태로 이동하고, 작업이 끝나면 다시 준비 상태로 돌아온다.

여러 프로세스를 동시에 다루기 위해 운영체제는 스케줄링을 한다. 선입선처리는 먼저 온 순서대로 처리하는 방식이고, 최단 작업 우선은 처리 시간이 짧은 작업을 먼저 실행하는 방식이다. 라운드 로빈은 각 프로세스에 일정 시간씩 CPU를 나누어 주는 방식이다. 어떤 방식이든 핵심은 제한된 CPU 시간을 여러 작업에 어떻게 나눠줄 것인가에 있다.

3. 메모리 관리는 실행 공간을 나누고 보호하는 일이다#

메모리 관리는 프로그램이 실행될 수 있도록 필요한 공간을 할당하고, 사용이 끝난 공간을 회수하는 작업이다. 여러 프로그램이 동시에 실행되면 메모리 공간을 효율적으로 나누는 것이 중요해진다.

초기 방식 중 하나는 고정 분할 방식이다. 메모리를 미리 정해진 크기로 나누고, 각 구역에 프로그램을 넣는 방식이다. 단순하지만 프로그램 크기와 분할 크기가 맞지 않으면 사용하지 못하는 공간이 생긴다. 내부 단편화는 할당된 공간 안에서 남는 공간이 생기는 문제이고, 외부 단편화는 빈 공간은 있지만 연속된 큰 공간이 없어 할당하지 못하는 문제다.

가변 분할 방식은 프로그램마다 필요한 만큼 다른 크기의 메모리를 할당한다. 고정 분할보다 유연하지만, 시간이 지나면 외부 단편화가 생길 수 있다.

가상 메모리는 실제 물리 메모리보다 더 큰 메모리를 쓰는 것처럼 보이게 하는 기술이다. 프로세스는 논리 주소를 사용하고, 운영체제는 이를 실제 물리 주소로 매핑한다. 이 덕분에 각 프로세스는 독립적인 주소 공간을 가진 것처럼 실행될 수 있고, 다른 프로세스의 메모리에 함부로 접근하지 못하게 보호할 수 있다.

페이징은 가상 메모리와 물리 메모리를 일정한 크기의 페이지와 프레임으로 나누어 관리하는 방식이다. 페이지 테이블은 가상 주소의 페이지가 실제 메모리의 어느 위치에 있는지 알려주는 표다. 사용하지 않는 페이지를 디스크로 잠시 옮기는 스와핑, 필요한 페이지를 실제로 필요할 때 가져오는 요구 페이징도 메모리를 효율적으로 쓰기 위한 방법이다.

4. 파일 시스템은 데이터를 찾기 쉽게 정리한다#

파일은 컴퓨터에서 정보를 담는 논리적인 저장 단위다. 파일에는 이름, 유형, 저장 위치, 크기, 만든 시간, 수정 시간 같은 메타데이터가 함께 관리된다. 디렉터리는 여러 파일을 계층적으로 정리하기 위한 특수한 파일이다.

파일 시스템은 사용자가 파일을 쉽게 저장하고 찾을 수 있도록 관리하는 체계다. 운영체제는 파일 시스템을 통해 보조기억장치 안의 데이터를 파일과 디렉터리 구조로 보여준다.

디스크에 파일을 배치하는 방식에는 여러 가지가 있다.

  • 연속 할당: 파일을 연속된 공간에 저장한다. 접근은 빠르지만 외부 단편화가 생길 수 있다.
  • 연결 할당: 각 블록이 다음 블록의 위치를 가리킨다. 공간 활용은 좋지만 중간 위치에 바로 접근하기 어렵다.
  • FAT 방식: 각 블록의 연결 정보를 별도 테이블에 저장한다.
  • 색인 할당: 파일마다 색인 블록을 두고 데이터 블록의 위치를 저장한다.

Linux 계열에서는 inode가 중요한 역할을 한다. inode는 파일의 실제 데이터 위치와 메타데이터를 관리하는 구조다. 파일 이름은 디렉터리에서 inode를 가리키고, inode는 다시 실제 데이터 블록을 가리킨다.

링크는 파일을 다른 이름이나 경로로 접근하게 해주는 기능이다. 심볼릭 링크는 원본 파일을 가리키는 별도의 바로가기 파일에 가깝고, 하드 링크는 같은 inode를 여러 파일 이름이 함께 가리키는 방식이다.

마운트는 물리적인 저장 장치를 특정 디렉터리에 연결하는 작업이다. Linux에서는 하드디스크, USB 메모리, CD/DVD 같은 장치를 /mnt, /media, 또는 특정 디렉터리에 연결해 하나의 디렉터리 트리 안에서 접근할 수 있게 한다.

마무리#

운영체제는 컴퓨터 자원을 직접 다루는 복잡함을 감추고, 프로그램이 안정적으로 실행될 수 있는 환경을 제공한다. 사용자는 파일을 열고 앱을 실행하는 것처럼 단순한 행동을 하지만, 그 뒤에서는 프로세스 관리, 메모리 관리, 파일 시스템 관리가 계속 일어난다.

1. 핵심 주장#

운영체제는 하드웨어와 프로그램 사이에서 자원을 관리하는 조정자다. CPU, 메모리, 저장장치, 네트워크 같은 제한된 자원을 여러 프로그램이 함께 사용할 수 있도록 나누고, 보호하고, 순서를 정한다.

운영체제를 이해하면 프로그램이 “왜 느려지는지”, “왜 메모리가 부족해지는지”, “왜 파일 경로와 권한이 중요한지"를 더 구조적으로 볼 수 있다.

2. 중요한 개념#

  • 운영체제는 하드웨어 자원을 관리하고 프로그램 실행 환경을 제공하는 시스템 소프트웨어다.
  • 프로세스는 실행 중인 프로그램이고, 스레드는 프로세스 안의 실행 흐름이다.
  • 프로세스는 코드, 데이터, 힙, 스택 영역을 가진다.
  • 스케줄링은 여러 프로세스에 CPU 시간을 나누어 주는 방식이다.
  • 메모리 관리는 필요한 공간을 할당하고 회수하며, 단편화 문제를 다룬다.
  • 가상 메모리는 프로세스가 독립적인 주소 공간을 가진 것처럼 실행되게 한다.
  • 페이징, 스와핑, 요구 페이징은 메모리를 효율적으로 사용하기 위한 기법이다.
  • 파일 시스템은 파일, 디렉터리, 메타데이터, 디스크 할당 방식을 관리한다.
  • inode, 링크, 마운트는 Linux 파일 시스템을 이해할 때 중요한 개념이다.

3. 내가 놓치기 쉬운 부분#

프로그램과 프로세스를 같은 말처럼 쓰기 쉽다. 하지만 프로그램은 저장된 코드이고, 프로세스는 그 코드가 실행 중인 상태다. 이 차이를 알아야 실행, 종료, 메모리 사용량, CPU 점유율 같은 개념이 더 잘 이해된다.

메모리도 단순히 “용량"으로만 보면 놓치는 것이 많다. 운영체제는 단순히 빈 공간을 찾아주는 것이 아니라, 각 프로세스가 서로의 영역을 침범하지 않도록 보호하고, 실제 메모리가 부족할 때 디스크까지 활용해 실행을 이어간다.

파일 역시 화면에 보이는 이름만이 전부가 아니다. 파일 이름, 메타데이터, inode, 실제 데이터 블록은 서로 다른 층위에서 관리된다. 그래서 링크, 권한, 마운트 같은 개념을 이해해야 파일 시스템을 더 정확히 다룰 수 있다.

4. 현실에 적용하는 방법#

작업 관리자를 볼 때 CPU, 메모리, 디스크 사용량을 단순한 숫자로만 보지 않고 운영체제가 어떤 자원을 배분하고 있는지 생각해볼 수 있다. 특정 프로그램이 느려졌다면 CPU를 많이 쓰는지, 메모리를 많이 쓰는지, 디스크 입출력이 몰리는지 나누어 볼 수 있다.

개발 환경에서는 프로세스와 포트, 파일 경로, 권한 문제가 자주 등장한다. 서버가 이미 실행 중인지 확인하거나, 특정 포트를 점유한 프로세스를 종료하거나, 로그 파일 위치와 권한을 확인하는 일은 모두 운영체제 지식과 연결된다.

Linux를 사용할 때는 파일을 단순히 저장하는 대상으로만 보지 않고, 디렉터리 구조, 심볼릭 링크, 마운트 위치를 함께 확인하는 습관을 들이면 좋다. 특히 Docker나 서버 환경을 다룰 때는 운영체제의 파일 시스템과 프로세스 개념이 거의 매일 등장한다.

5. 나에게 물어볼 질문 5개#

  1. 내가 실행한 프로그램은 운영체제 안에서 어떤 프로세스로 관리되고 있을까?
  2. 프로세스와 스레드의 차이를 실제 사용하는 앱의 예시로 설명할 수 있을까?
  3. 메모리가 부족할 때 운영체제는 어떤 방식으로 실행을 이어가려고 할까?
  4. 파일 이름과 실제 파일 데이터는 운영체제 안에서 어떻게 연결되어 있을까?
  5. Linux에서 심볼릭 링크, 하드 링크, 마운트가 필요한 상황을 각각 떠올릴 수 있을까?
