    [이어드림스쿨6기_1개월] 01 IT 리터러시

    2026년 5월 31일

    강의자료/01 IT 리터러시 이어드림스쿨 강의자료를 바탕으로, 비개발자도 개발자와 더 정확하게 대화할 수 있도록 핵심 개념을 한 번에 정리해 보았다.

    IT 리터러시는 코드를 직접 짜는 능력만을 뜻하지 않는다. 컴퓨터가 어떻게 정보를 처리하는지, 웹과 앱 서비스가 어떤 구조로 움직이는지, 데이터와 API가 왜 중요한지, 그리고 현업에서 자주 쓰는 용어가 어떤 맥락에서 등장하는지를 이해하는 능력에 가깝다.

    1. 컴퓨터는 0과 1로 소통한다#

    컴퓨터의 가장 아래에는 0과 1이 있다. 전기가 켜져 있으면 1, 꺼져 있으면 0처럼 단순한 신호를 조합해 복잡한 정보를 표현한다. 사람이 쓰는 언어와 컴퓨터가 이해하는 언어 사이에는 큰 간격이 있기 때문에, 개발자는 프로그래밍 언어를 사용해 컴퓨터와 소통한다.

    프로그래밍 언어는 컴퓨터 위에서 실행되는 명령을 사람이 읽고 쓰기 좋게 만든 도구다. JavaScript, Python, Java, C, Kotlin, Swift처럼 다양한 언어가 있고, 각 언어는 쓰임새와 강점이 조금씩 다르다. 우리가 작성한 코드는 인터프리터나 컴파일러 같은 과정을 거쳐 컴퓨터가 처리할 수 있는 형태로 바뀐다.

    운영체제도 중요한 역할을 한다. Windows, macOS, Linux, Android, iOS 같은 운영체제는 컴퓨터나 스마트폰의 자원을 관리하고, 앱이 실행될 수 있는 환경을 제공한다. 같은 서비스라도 어떤 운영체제에서 실행되는지에 따라 고려해야 할 점이 달라진다.

    2. 웹과 앱 서비스는 요청과 응답으로 움직인다#

    우리가 웹사이트나 앱을 사용할 때는 보통 다음과 같은 흐름이 일어난다.

    1. 사용자가 화면에서 어떤 행동을 한다.
    2. 브라우저나 앱이 서버에 요청을 보낸다.
    3. 서버는 필요한 데이터를 찾거나 처리한다.
    4. 서버가 응답을 돌려준다.
    5. 화면이 사용자에게 결과를 보여준다.

    이때 자주 등장하는 개념이 HTTP다. HTTP는 클라이언트와 서버가 대화하는 규칙이다. GET은 정보를 가져올 때, POST는 새 정보를 보낼 때, PUT이나 PATCH는 정보를 수정할 때, DELETE는 정보를 삭제할 때 주로 쓰이는 통신함수이다.

    프론트엔드는 사용자가 직접 만나는 화면이다. 버튼, 입력창, 로그인 화면, 반응형 화면, UI와 UX가 여기에 속한다. 백엔드는 화면 뒤에서 비즈니스 로직을 처리하고 데이터베이스와 통신한다. 사용자는 화면만 보지만, 실제 서비스는 프론트엔드, 백엔드, 데이터베이스가 함께 움직이면서 완성된다.

    3. 데이터베이스는 서비스를 기억하게 만든다#

    데이터베이스는 기록하고 조회하는 모든 데이터의 집합이다. 쇼핑몰을 예로 들면 상품명, 가격, 재고, 회원 정보, 주문 내역, 결제 상태 같은 정보가 데이터베이스에 저장된다.

    데이터베이스의 기본 기능은 보통 네 가지로 설명할 수 있다.

    • 저장: 새로운 데이터를 저장한다.
    • 검색: 조건에 맞는 데이터를 찾는다.
    • 수정: 기존 데이터를 바꾼다.
    • 삭제: 필요 없는 데이터를 지운다.

    이 흐름은 서비스 기능과 바로 연결된다. 상품을 등록하면 생성이고, 상품 목록을 보면 조회이며, 가격을 바꾸면 수정이고, 판매 종료 상품을 지우면 삭제다. 그래서 서비스를 기획할 때도 “어떤 데이터를 만들고, 읽고, 바꾸고, 지울 것인가"를 생각하면 구조가 훨씬 선명해진다.

    API는 프로그램끼리 대화하기 위한 약속이다. 예를 들어 로그인 API는 아이디와 비밀번호를 받아 확인하고, 성공 여부와 사용자 정보를 돌려준다. 지도, 결제, 배송 조회, 상품 검색처럼 외부 서비스의 기능을 가져올 때도 API가 핵심 통로가 된다.

    4. 라이브러리와 프레임워크는 개발 속도를 높인다#

    라이브러리는 자주 쓰는 기능을 모아 둔 코드 묶음이다. 차트를 그릴 때 Chart.js를 쓰거나, 인증 처리를 위해 Passport.js 같은 도구를 쓰는 식이다. 모든 기능을 처음부터 직접 만들 필요가 없기 때문에 생산성과 효율성이 좋아진다.

    프레임워크는 더 큰 틀을 제공한다. 개발자가 정해진 구조 안에서 필요한 코드를 채워 넣도록 도와주는 도구라고 볼 수 있다. 같은 작업을 반복하지 않게 해주고, 프로젝트의 구조를 일정하게 유지하는 데 도움을 준다.

    둘의 차이를 단순하게 말하면, 라이브러리는 내가 필요할 때 불러 쓰는 도구에 가깝고 프레임워크는 작업 방식의 뼈대를 제공하는 환경에 가깝다.

    5. SEO는 검색엔진과 잘 대화하는 작업이다#

    SEO는 검색엔진 최적화다. 좋은 콘텐츠를 만들었더라도 검색엔진이 페이지를 제대로 찾고 이해하지 못하면 사용자에게 노출되기 어렵다.

    검색엔진은 웹페이지를 크롤링하고, 내용을 분석해 색인한 뒤, 사용자의 검색어에 맞춰 결과를 보여준다. 이 과정에서 제목, 설명, 페이지 구조, 링크, 키워드, 사이트맵, 페이지 속도, 모바일 대응 등이 영향을 준다.

    크롤링은 컴퓨터가 웹페이지를 자동으로 방문해 코드를 읽는 과정이다. 검색엔진뿐 아니라 가격 비교, 데이터 수집, 아카이빙 같은 다양한 목적으로도 쓰인다. 다만 모든 사이트가 무제한 크롤링을 허용하는 것은 아니므로, 서비스 약관과 robots.txt 같은 기준을 함께 확인해야 한다.

    6. 현업 용어를 알면 협업이 쉬워진다#

    실무에서는 기술 자체만큼이나 용어가 중요하다. 같은 말을 다르게 이해하면 기획, 디자인, 개발, 운영 사이에서 불필요한 오해가 생긴다.

    버전 컨트롤은 프로젝트의 변경 이력을 관리하는 방법이다. Git은 대표적인 버전 관리 도구이며, GitHub나 Bitbucket 같은 서비스는 Git 기반 협업을 더 편하게 해준다. 문제가 생겼을 때 이전 상태로 돌아가거나, 여러 사람이 동시에 작업한 내용을 합치는 데 필요하다.

    플로우차트는 서비스의 핵심 흐름을 시각적으로 정리하는 도구다. 쇼핑몰이라면 “상품 페이지 접속 → 상품 구매 → 배송"처럼 사용자의 행동과 시스템의 처리를 한눈에 볼 수 있다. 개발 전에 플로우를 정리하면 필요한 화면, 데이터, API를 더 정확하게 파악할 수 있다.

    오픈소스는 공개적으로 사용할 수 있는 코드나 프로젝트를 뜻한다. Android, Linux처럼 널리 알려진 사례도 있고, 작은 라이브러리나 도구도 많다. 오픈소스를 활용하면 개발 속도를 높일 수 있지만, 라이선스와 유지보수 상태를 확인하는 습관이 필요하다.

    클라우드는 서버를 직접 구매하고 관리하지 않아도 인터넷을 통해 필요한 컴퓨팅 자원을 쓰게 해주는 방식이다. AWS, Microsoft Azure, Google Cloud 같은 서비스가 대표적이다. SaaS는 클라우드 기반으로 제공되는 소프트웨어 서비스다. Figma, Notion, Google Workspace처럼 설치보다 접속과 구독이 중심이 되는 도구들이 여기에 해당한다.

    마무리#

    이번 강의의 핵심은 IT 리터러시가 단순한 용어 암기가 아니라, 서비스를 구조적으로 이해하기 위한 관점이라는 점이다. 컴퓨터, 웹, 데이터베이스, API, 라이브러리, 프레임워크, SEO, 협업 용어는 각각 따로 떨어진 개념처럼 보이지만 실제 서비스 안에서는 서로 연결되어 움직인다.

    1. 핵심 주장#

    IT 리터러시는 개발자가 되기 위한 사전 시험이 아니다. 서비스를 더 잘 이해하고, 개발자와 더 정확히 대화하고, 기획의 빈틈을 더 빨리 발견하기 위한 공통 언어다.

    서비스를 만들거나 분석할 때는 “화면이 예쁜가?“에서 멈추지 않고, 사용자의 행동이 어떤 요청으로 바뀌는지, 서버는 어떤 데이터를 처리하는지, 그 결과가 다시 화면에 어떻게 돌아오는지를 함께 봐야 한다.

    2. 중요한 개념#

    • 컴퓨터는 0과 1이라는 신호를 바탕으로 정보를 처리한다.
    • 프로그래밍 언어는 사람이 컴퓨터에게 명령을 전달하기 위한 중간 언어다.
    • 웹과 앱 서비스는 클라이언트의 요청과 서버의 응답으로 움직인다.
    • 데이터베이스는 서비스가 기억해야 할 정보를 저장, 검색, 수정, 삭제한다.
    • API는 프로그램과 프로그램이 정해진 방식으로 대화하게 해주는 통로다.
    • 라이브러리와 프레임워크는 반복되는 개발 작업을 줄이고 구조를 잡아준다.
    • SEO는 검색엔진이 내 콘텐츠를 잘 발견하고 이해하도록 돕는 작업이다.
    • Git, 플로우차트, 오픈소스, 클라우드, SaaS 같은 용어는 현업 협업에서 자주 쓰이는 기본 언어다.

    3. 내가 놓치기 쉬운 부분#

    가장 놓치기 쉬운 부분은 용어를 단어 그대로만 외우는 것이다. 예를 들어 API를 “데이터를 주고받는 것” 정도로만 이해하면 실제 서비스에서 어떤 요청이 오가고, 어떤 데이터가 필요하며, 어디에서 문제가 생길 수 있는지까지 생각하기 어렵다.

    또 하나는 프론트엔드와 백엔드를 너무 분리해서 보는 것이다. 사용자는 화면만 보지만, 화면의 버튼 하나도 서버 요청, 데이터베이스 조회, 응답 처리와 연결된다. 그래서 기획 단계에서 화면 흐름만 정리하는 것이 아니라 데이터 흐름까지 함께 생각해야 한다.

    SEO 역시 글을 올린 뒤에 하는 부가 작업으로만 보면 놓치는 것이 많다. 제목, 구조, 키워드, 링크, 페이지 속도, 모바일 대응은 콘텐츠를 만들 때부터 같이 고려해야 검색엔진과 사용자 모두에게 친절한 페이지가 된다.

    4. 현실에 적용하는 방법#

    앞으로 서비스를 볼 때는 화면보다 먼저 흐름을 그려보려고 한다. 예를 들어 쇼핑몰을 분석한다면 “상품 조회 → 장바구니 담기 → 주문 → 결제 → 배송 조회"처럼 사용자의 행동을 나누고, 각 단계에서 어떤 데이터와 API가 필요할지 생각해볼 수 있다.

    프로젝트를 기획할 때는 플로우차트와 데이터 목록을 함께 작성하면 좋다. 어떤 화면이 필요한지, 어떤 데이터가 저장되어야 하는지, 어떤 요청이 서버로 가야 하는지 정리하면 개발자와 대화할 때 훨씬 구체적인 질문을 할 수 있다.

    또한 새로운 기술 용어를 만났을 때는 “정의”, “쓰는 이유”, “서비스 안에서 연결되는 위치"를 함께 정리해보려고 한다. 이렇게 해야 단순 암기가 아니라 실제 문제 해결에 쓸 수 있는 지식이 된다.

    5. 나에게 물어볼 질문 5개#

    1. 내가 사용하는 앱이나 웹서비스에서 사용자의 행동은 어떤 요청과 응답으로 이어질까?
    2. 이 서비스가 반드시 기억해야 하는 데이터는 무엇이고, 그 데이터는 언제 생성, 조회, 수정, 삭제될까?
    3. 프론트엔드 화면에서 보이는 기능 중 백엔드와 데이터베이스가 함께 움직이는 부분은 어디일까?
    4. 내가 기획서를 쓴다면 개발자가 바로 이해할 수 있도록 플로우차트와 API 흐름을 설명할 수 있을까?
    5. 지금 알고 있는 IT 용어 중 뜻은 알지만 실제 서비스 안에서 어떻게 쓰이는지 설명하기 어려운 개념은 무엇일까?
