선형대수학 (행렬과 벡터)#

개발에 선형대수학이 필요한 이유#

  • 시나리오 : 비즈니스에 이미지 데이터를 저장하고 있음
  • 문제점 : 원본 이미지를 저장시, 고차원 데이터 => 저장비용 증가 => 고정비 상승
  • 해결방안 : PCA 원리를 활용
    • 하드웨어 투자를 하기에 앞서서, 이미지를 압축해서 저장하는 스킬
    • 행렬 분해(SVD/PCA) 활용하면 이미지 저장 비용이 줄어든다!
    • 시간적으로 처리속도 증가하고, 저장비용도 감소함

SVD와 PCA는 둘 다 고차원 데이터를 더 단순하게 표현하는 방법

SVD(Singular Value Decomposition): 행렬을 여러 개의 작은 행렬로 분해하는 수학적인 방법

PCA(Principal Component Analysis): 데이터의 중요한 특징만 남기고 차원을 줄이는 통계 기법

행렬의 정의#

  • 행렬(matrix)은 수나 식을 직사각형 모양으로 배열
  • 일반적으로 m개의 행과 n개의 열을 배열하여 m * n 행렬을 구성
  • 같은 수의 행과 열을 가지면 정방행렬(square matrix) 부름
  • 1 * n 행렬은 행벡터, n * 1 행렬은 열벡터라고 부름, 전치연산자(T)를 통해 행과 열을 서로 바꿀 수 있다
  • 크기가 같은 두 행렬은 같은 위치의 성분끼리 덧셈, 뺄셈, 스칼라 곱셈이 가능하다.
  • 행렬은 곧 영역 전개이다.

행렬의 연산 예시#

  • 시나리오 : 영화 추천 별점 예상. 철수(액션), 영희(로맨스), 민수(다 좋아함)
    • 유저 행렬 : 얼마나 좋아하는가?
    • 영화 행렬 : 영화별 장르 성분이 얼마나 들어있는가?
    • 유저 3명 (성향 행렬) => U
    • 영화 3편 (성분 행렬) => V
import numpy as np
users = ["Cheolsu (Action)", "Younghee (Romance)", "Minsu (Both)"]

# 유저 성향 점수를 행렬로 생성
U = np.array([
    [5, 1], # 철수는 액션 5, 로맨스 1
    [1, 5], # 영희는 액션 1, 로맨스 5
    [4, 4]  # 민수는 액션 4, 로맨스 4
])

# 영화 장르별 성분을 행렬로 생성
# 열 : 영화
# 행 : 액션 비중, 로맨스 비중 (1.0 만점 기준)
movies = ["Die Hard", "Titanic", "Terminator"]
V_T = np.array([
    [1.0, 0.0, 0.9], # 액션 비중
    [0.0, 1.0, 0.1]  # 로맨스 성분 비중
])

# 선형대수 행렬 곱셈 연산
predicted_ratings = U @ V_T
predicted_ratings

결과 : [5. , 1. , 4.6]  # 철수의 영화 평점
       [1. , 5. , 1.4]  # 영희의 영화 평점
       [4. , 4. , 4. ]  # 민수의 영화 평점

벡터 공간(R^n)#

  • 실수 n개로 이루어진 모든 벡터들이 모여 있는 공간
  • 분석가가 ‘고객을 바라보는 렌즈의 갯수(변수)‘를 늘려가는 과정
  • 고객의 나이, 구매액 (2차원)
  • 고객의 나이, 구매액, 방문횟수 (3차원)
  • 분석을 하려면 더 많은 요인이 필요해 => R^n 의 대수학적 확장
    • 추천 알고리즘 : 클릭 횟수, 체류 시간, 반품 이력… 등 수백개의 변수 추가
    • 100개의 변수 활용, 100차원 (R^100)
  • 두 가지 필수 연산의 의미
    • 벡터의 덧셈 : 온라인 쇼핑 행동 벡터 + 오프라인 매장 행동 벡터 => 고객의 통합 프로파일(Omni-Channel Profile) 완성
    • 스칼라 곱 : 마케팅 목표 설정, 현재 우수 고객 모든 활동량을 1.5배 곱을 한다. 기존 고객 벡터의 방향성(취향)은 유지한 채, 규모를 스케일업(Scale-Up) 시뮬레이션
import numpy as np

# 벡터 (구매 횟수, 사이트 체류시간)
online_behavior = np.array([4, 2])
offline_behavior = np.array([1, 4])
scalar_growth = 1.5   # 가중치

# 벡터의 덧셈 : 두 행동 양식을 더해서, 옴니채널 통합 벡터 생성
integrated_v = online_behavior + offline_behavior
print(integrated_v)

# 스칼라 곱 : 통합된 고객 행동을 일정 비율로 스케일업
scaled_v = integrated_v * scalar_growth
print(scaled_v)

결과 : [5 6]     # 온라인·오프라인 행동을 통합한 고객 행동 생성
      [7.5 9. ]  # 고객 행동이 전체적으로 1.5배 증가했다고 가정

코사인 유사도#

  • 두 벡터의 내적을 각 벡터의 크기(Norm)의 곱으로 나눈 값이다.

활용 예시#

  • 콘텐츠 플랫폼 취향 매칭
    • 고객 A (헤비 유저) : 주말 내내 영화 시청 (액션 100시간, 로맨스 10시간, SF 50시간)
    • 고객 B (라이트 유저) : 한달에 한두편 시청 (액션 10시간, 로맨스 1시간, SF 5시간)
  • 두 고객의 절대적인 시청량(크기) 차이를 무시 => 장르별 비율(방향)이 같은지 확인
import numpy as np
from sklearn.metrics.pairwise import cosine_similarity

customer_A = np.array([100, 10, 50])
customer_B = np.array([10, 1, 5])

# 방식 1. Norm과 내적 직접 구현
dot_product = np.dot(customer_A, customer_B)
norm_A = np.linalg.norm(customer_A)
norm_B = np.linalg.norm(customer_B)

# 코사인 유사도 공식 적용
cos_sim_manual = dot_product / (norm_A * norm_B)
print(cos_sim_manual)

# 코사인 유사도 더 쉽게 계산
# 머신러닝 라이브러리 scikit-learn 방식
# 기본 입력값이 2차원 배열
A_2d = customer_A.reshape(1, -1)
B_2d = customer_B.reshape(1, -1)

cosine_similarity(A_2d, B_2d)[0][0]

선형방정식#

수학적 원리#

  • 제약 조건 속 최적의 해답 찾기
  • 행렬과 벡터를 활용하여 Ax = b 형태의 수식으로 표현
  • 방정식을 풀기 위해 미지수의 계수(행렬 A)와 우변의 상수(벡터 b)를 하나로 합친 첨가 행렬(Augmented Matrix) 구성
  • 미지수를 규칙적으로 줄여나가는 Gauss 소거법
  • 대각선 성분만 남기는 사다리꼴 행렬로 만드는 Gauss-Jordan 소거법

비즈니스 관점에서 바라보기#

  • 제약조건 1(예산), 제약조건 2(시간) ==> 가장 효율적인 접점 ==> 황금비율 찾기
  • 선형방정식을 푼다는 의미는 비즈니스 현장에서 ‘수많은 제약조건이 있는데, 그 중에서 최적의 자원 배분 비율(황금비율)을 찾는 과정’
  • 예시
    • 광고채널 A(x)와 광고채널 B(y)의 최적 집행 횟수 찾기
    • 제약조건 1 (예산) : 3x + 1y = 9 (총 예산 900만원 소진)
    • 제약조건 2 (시간) : 1x + 2y = 8 (총 가용 시간 80시간 소진)
# 선형방정식 행렬 세팅(Ax = b)
# 계수 행렬 A
A_matrix = np.array([
    [3, 1],
    [1, 2]
])

# 상수 벡터 b
b_vector = np.array([9, 8])

# 선형방정식 풀이 (np.linalg.solve() 활용)
solution = np.linalg.solve(A_matrix, b_vector)
x_sol, y_sol = solution
print(x_sol, y_sol)

결과 : 2.0 3.0
  • 수학적인 의미
    • 두 선형 방정식 3x + y = 9, x + 2y = 8을 동시에 만족하는 유일한 해(solution)가 기하학적으로 두 직선의 교점과 같음
  • 비즈니스적 의미
    • 한정된 예산과 시간을 최대한 활용하면서, 최대의 효율을 내기 위해, 광고 채널 A에 2회 집행, 채널 B에 3회 집행 => 최적 자원 배분
