데이터 분류 모델 RandomForestClassifier Lv4#

이번 글에서는 seaborn Titanic 데이터로 승객 생존 여부(survived) 를 예측하는 분류 모델을 정리한다.

Lv4의 핵심은 단순히 모델을 바꾸는 것이 아니라, 분류 문제에서 검증 설계와 튜닝 순서를 제대로 잡는 것이다.

  • 타깃: survived (0=사망, 1=생존)
  • 모델: RandomForestClassifier
  • 분리 방식: train_test_split(..., stratify=y)
  • 교차검증: StratifiedKFold
  • 튜닝: GridSearchCV
  • 전처리: Pipeline + ColumnTransformer
  • 평가: classification_report, ROC-AUC, confusion_matrix

새로 학습한 내용#

이번 Lv4에서 새로 봐야 할 핵심은 다음과 같다.

RandomForestClassifier는 여러 개의 의사결정나무를 만들고, 각 나무의 예측을 모아 최종 분류 결과를 정하는 앙상블 모델이다. 하나의 결정나무보다 과적합에 덜 민감하고, 비선형 패턴을 잘 잡는 편이다.

stratify=y는 학습/테스트 데이터가 원래 타깃 비율을 비슷하게 유지하도록 나누는 옵션이다. Titanic 데이터는 사망/생존 비율이 완전히 같지 않기 때문에, 분류 평가를 안정적으로 하려면 층화추출이 중요하다.

StratifiedKFold는 교차검증의 각 fold에서도 클래스 비율을 유지하는 방법이다. 회귀에서 사용했던 KFold와 달리, 분류 문제에서는 각 fold 안의 사망/생존 비율이 크게 흔들리지 않도록 관리한다.

GridSearchCV는 여러 하이퍼파라미터 조합을 자동으로 실험하고, 교차검증 점수가 가장 좋은 조합을 찾아준다. 이번 예제에서는 roc_auc를 기준으로 최적 조합을 선택한다.

predict_proba()는 각 클래스에 속할 확률을 반환한다. ROC-AUC는 단순 예측값 0/1보다 생존 확률 점수를 이용해 모델의 구분 능력을 평가한다.

Pipeline 구성#

numeric_transformer = Pipeline(steps=[
    ("imputer", SimpleImputer(strategy="median")),
    ("scaler", StandardScaler()),
])

categorical_transformer = Pipeline(steps=[
    ("imputer", SimpleImputer(strategy="most_frequent")),
    ("onehot", OneHotEncoder(
        drop="first",
        handle_unknown="ignore",
        sparse_output=False,
    )),
])

preprocessor = ColumnTransformer(transformers=[
    ("num", numeric_transformer, numeric_features),
    ("cat", categorical_transformer, categorical_features),
])

rf_model = RandomForestClassifier(
    n_estimators=200,
    random_state=RANDOM_STATE,
    n_jobs=-1,
)

pipeline = Pipeline(steps=[
    ("preprocessor", preprocessor),
    ("model", rf_model),
])

pipeline

RandomForestClassifier의 주요 설정은 다음과 같다.

  • n_estimators=200: 200개의 결정나무를 만든다.
  • random_state=42: 결과 재현을 위해 난수 시드를 고정한다.
  • n_jobs=-1: 가능한 CPU 코어를 사용해 병렬 처리한다.

OneHotEncoder(drop="first")는 범주형 변수를 원-핫 인코딩할 때 첫 번째 범주를 하나 제거한다. 중복 더미 변수를 줄이는 효과가 있다. sparse_output=False는 결과를 희소 행렬이 아니라 일반 배열 형태로 반환하도록 하는 설정이다.

StratifiedKFold 교차검증#

cv = StratifiedKFold(

GridSearchCV 하이퍼파라미터 튜닝#

param_grid = {
    "model__n_estimators": [100, 200],
    "model__max_depth": [3, 5, None],
    "model__min_samples_leaf": [1, 3, 5],
    "model__max_features": ["sqrt", "log2"],
}

grid_search = GridSearchCV(
    estimator=pipeline,
    param_grid=param_grid,
    scoring="roc_auc",
    cv=cv,
    n_jobs=-1,
    return_train_score=True,
)

grid_search.fit(X_train, y_train)

RandomForest에서 자주 조정하는 하이퍼파라미터는 다음과 같다.

  • n_estimators: 만들 나무의 개수
  • max_depth: 각 나무의 최대 깊이
  • min_samples_leaf: 마지막 leaf node에 있어야 하는 최소 샘플 수
  • max_features: 각 split에서 고려할 feature 수

GridSearchCV에서 파이프라인 내부 모델의 파라미터를 지정할 때는 model__max_depth처럼 단계이름__파라미터명 형식을 사용한다. 여기서 model은 Pipeline에서 붙인 단계 이름이다.

정리#

이번 Lv4 분류 예제의 핵심 흐름은 다음과 같다.

  1. survived를 타깃으로 하는 이진 분류 문제를 만들었다.
  2. 학습/테스트 분리에서 stratify=y로 클래스 비율을 유지했다.
  3. 수치형·범주형 변수를 분리하고 ColumnTransformer로 전처리했다.
  4. Pipeline으로 전처리와 RandomForestClassifier를 하나로 묶었다.
  5. StratifiedKFold로 층화 교차검증을 진행했다.
  6. GridSearchCV로 RandomForest 하이퍼파라미터를 튜닝했다.
  7. 마지막에만 테스트 데이터로 최종 성능을 평가했다.
  8. 혼동행렬과 특성 중요도로 모델 결과를 해석했다.

Lv4에서 가장 중요한 메시지는 테스트 데이터는 마지막 평가에만 사용한다는 점이다. 전처리, 교차검증, 튜닝은 모두 학습 데이터 내부에서만 진행해야 모델 성능을 더 정직하게 확인할 수 있다.
