새로 학습한 머신러닝 도구#

이번 노트북에서 새롭게 봐야 할 머신러닝 도구는 KFold와 cross_validate다.

KFold는 학습 데이터를 K개의 조각으로 나누는 교차검증 방식이다. 예를 들어 n_splits=5로 설정하면 데이터를 5개 fold로 나눈다. 그다음 4개 fold로 학습하고, 남은 1개 fold로 검증하는 과정을 5번 반복한다.

cross_validate는 위 과정을 자동으로 실행하고, 여러 평가 지표를 한 번에 계산해준다. 이번 예제에서는 RMSE, MAE, R2를 동시에 확인한다.

또 하나 중요한 점은 return_train_score=True다. 이 옵션을 켜면 검증 점수뿐 아니라 학습 점수도 함께 볼 수 있다. 학습 점수는 매우 좋은데 검증 점수가 낮다면 모델이 학습 데이터만 외운 과적합 상태일 수 있다.

반복되는 전처리 함수화#

X_train에서 한 전처리를 X_test에도 똑같이 적용해야 한다. 이때 전처리 코드를 함수로 묶어두면 같은 규칙을 재사용할 수 있고, train/test에 서로 다른 처리를 적용하는 실수를 줄일 수 있다.

def prepare_house_features(data):
    prepared = data.copy()

    prepared.loc[:, "HouseAge"] = (
        prepared.loc[:, "YrSold"] - prepared.loc[:, "YearBuilt"]
    )
    prepared.loc[prepared.loc[:, "HouseAge"] < 0, "HouseAge"] = 0

    prepared.loc[:, "TotalSF"] = (
        prepared.loc[:, "GrLivArea"] + prepared.loc[:, "TotalBsmtSF"]
    )

    prepared.loc[:, "TotalBath"] = (
        prepared.loc[:, "FullBath"]
        + 0.5 * prepared.loc[:, "HalfBath"]
        + prepared.loc[:, "BsmtFullBath"]
        + 0.5 * prepared.loc[:, "BsmtHalfBath"]
    )

    garage_missing = prepared.loc[:, "GarageCars"].isnull()
    prepared.loc[:, "HasGarage"] = np.where(
        garage_missing,
        np.nan,
        (prepared.loc[:, "GarageCars"] > 0).astype(int),
    )

    prepared.loc[:, "QualBand"] = pd.cut(
        prepared.loc[:, "OverallQual"],
        bins=[0, 5, 7, 10],
        labels=["보통이하", "좋음", "매우좋음"],
        include_lowest=True,
    ).astype("object")

    prepared.loc[:, "AgeBand"] = pd.cut(
        prepared.loc[:, "HouseAge"],
        bins=[-1, 20, 50, 200],
        labels=["신축", "중년", "오래됨"],
    ).astype("object")

    return prepared.loc[:, model_features].copy()

중요한 점은 이 함수가 결측치 대체와 표준화를 직접 하지 않는다는 것이다. 결측치 처리와 표준화는 뒤에서 Pipeline 내부에서 수행한다.

Decision Tree 회귀 모델 만들기#

numeric_transformer = Pipeline([
    ("imputer", SimpleImputer(strategy="median")),
    ("scaler", StandardScaler()),
])

categorical_transformer = Pipeline([
    ("imputer", SimpleImputer(strategy="most_frequent")),
    ("onehot", OneHotEncoder(handle_unknown="ignore")),
])

preprocessor = ColumnTransformer([
    ("num", numeric_transformer, numeric_model_features),
    ("cat", categorical_transformer, categorical_model_features),
])

tree_model = DecisionTreeRegressor(
    max_depth=5,
    min_samples_leaf=10,
    random_state=RANDOM_STATE,
)

pipeline = Pipeline([
    ("preprocessor", preprocessor),
    ("model", tree_model),
])

pipeline

max_depth와 min_samples_leaf는 이번 모델에서 중요한 새 설정이다.

max_depth=5는 의사결정나무의 최대 깊이를 5로 제한한다. 나무가 너무 깊어지면 학습 데이터의 세세한 패턴까지 외워 과적합될 수 있다.

min_samples_leaf=10은 마지막 잎 노드에 최소 10개의 데이터가 있어야 한다는 뜻이다. 너무 적은 데이터만 보고 결론을 내리는 작은 가지를 줄여 과적합을 완화한다.

get_feature_names_out()은 ColumnTransformer와 OneHotEncoder를 지난 뒤 실제 모델에 들어간 최종 컬럼명을 가져온다. 원-핫 인코딩 이후에는 QualBand_매우좋음처럼 컬럼이 여러 개로 늘어나기 때문에, 이 메서드가 있어야 특성 중요도를 사람이 해석할 수 있다.

feature_importances_는 의사결정나무 모델이 예측에 어떤 변수를 많이 사용했는지를 보여준다. 값이 클수록 모델이 해당 변수를 중요하게 썼다는 뜻이다.

이 모델에서는 QualBand_매우좋음과 TotalSF가 가장 큰 영향을 준다. 즉 주택 품질이 매우 좋은지, 그리고 총 면적이 얼마나 큰지가 판매 가격 예측에서 핵심적인 역할을 했다.

정리#

이번 Lv3 회귀 예제의 핵심은 다음과 같다.

  1. 가격과 관련 있어 보이는 독립변수 일부를 선택했다.
  2. train_test_split 이후 파생변수와 바이닝을 진행해 데이터 누수를 줄였다.
  3. 먼저 X_train에서 수동으로 전처리한 뒤, 같은 과정을 prepare_house_features() 함수로 묶었다.
  4. 결측치 처리, 표준화, 원-핫 인코딩은 Pipeline 내부에서 수행했다.
  5. max_depth, min_samples_leaf로 의사결정나무의 복잡도를 제한했다.
  6. KFold와 cross_validate로 5-Fold 교차검증을 진행했다.
  7. 실제값과 예측값을 시각화하고, feature_importances_로 모델이 중요하게 본 변수를 확인했다.

Lv1이 회귀 모델의 기본 흐름을 익히는 예제였다면, Lv3는 실제 프로젝트에 가까운 흐름이다. 전처리 로직을 함수화하고, 파이프라인 안에서 학습 데이터 기준으로만 변환을 수행하며, 교차검증으로 성능을 확인하는 구조가 핵심이다.
